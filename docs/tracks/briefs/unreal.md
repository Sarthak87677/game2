TRACK: unreal — branch `claude/track-unreal`

Goal: scaffold the principal Unreal Engine 5 game client so the project is resumable on a machine with UE installed,
without pretending it builds here (there is no Unreal, no GPU in the sandbox — say so in every doc you write).

Deliverables (all under `unreal/TerraInfinite/` unless noted):
1. `TerraInfinite.uproject` (UE 5.4+; plugins: CesiumForUnreal, ChaosVehiclesPlugin, MassEntity/MassCrowd/MassTraffic
   (or note the marketplace requirement), Niagara, Water, PCG, ModelingToolsEditorMode off, EnhancedInput).
2. `Config/DefaultEngine.ini` (Nanite, Lumen GI/reflections, Virtual Shadow Maps, TSR, World Partition + HLOD, streaming
   settings), `DefaultGame.ini`, `DefaultInput.ini` (Enhanced Input actions: move, look, jump, interact, enter/exit
   vehicle, camera cycle, horn, lights, indicators), `DefaultScalability.ini` with Low/Medium/High/Ultra/Performance
   groups following the degradation order (distant shadows → reflections → foliage density → traffic density → draw
   distance before nearby building/player quality), dynamic resolution and TSR defaults, 60-FPS Performance Mode.
3. `Source/TerraInfinite/` C++ module: `TerraInfinite.Build.cs`, `TerraGameMode`, `TerraPlayerCharacter` (walk, run,
   stairs, elevator volumes, parkour zones with jump assist, fall protection fade-to-respawn), `TerraVehiclePawn`
   (Chaos vehicle with lights/indicators/horn/wipers/damage FX/stuck reset), `UGeoStreamingSubsystem` (cell streaming
   around the player, budget, unload), `UInteriorGeneratorSubsystem` (deterministic coordinate-seeded interior plans
   by category, Level Instance spawning, hero handcrafted layouts), `UJourneySubsystem` (rail/air/marine state
   machines, passenger camera), `UPerfDiagnosticsSubsystem` (current/avg/1 % low FPS, frame time, memory, VRAM via RHI
   stats, active cells, actors, draw calls; hardware probe: CPU/GPU/RAM/VRAM/resolution/RHI; writes a benchmark JSON),
   `UActivitySubsystem`. Headers + .cpp with real, compilable-looking code (no TODO stubs that hide missing logic; where
   a system is a skeleton, say so in a comment and in docs).
4. `Content/Data/` JSON data tables generated by `scripts/export-unreal-data.mjs` from `src/data/maharashtra/**`
   (destinations, spawns, stations, corridors, airports, ports, water routes, campus spec, interior grammar
   parameters) plus a UE `UDataTable` row struct header for each.
5. `Config/Secrets.ini.example` (Cesium ion token, Google Photorealistic 3D Tiles key) and `.gitignore` entries so
   real keys never enter source; document the licensing conditions for Google 3D Tiles and the legal fallbacks
   (Cesium World Terrain / open terrain, OSM buildings, Natural Earth, open railway/road/airport data).
6. `docs/UNREAL.md`: exact installation requirements (UE 5.4+ via Epic Games Launcher, Visual Studio 2022 with
   "Game development with C++" + Windows 10/11 SDK, or Xcode 15 on macOS; Cesium for Unreal from Fab; ~150 GB disk;
   a GPU with ≥ 8 GB VRAM for Nanite/Lumen at 1080p60), build steps, how to run the benchmark map, and the
   verification gates that remain open until it runs on a real machine.
7. A unit test in this repo for the exporter (`tests/unit/exportUnrealData.test.ts`) so the shared data stays in sync.
Do not modify `src/**` except the exporter's read-only imports.
