# Terra Infinite — Unreal Engine 5 client

**Status: scaffold only. Nothing under `unreal/` has ever been compiled or opened in an editor.** This repository is
developed in a cloud sandbox that has no Unreal Engine install and no GPU, so the Unreal client was written "blind"
against the UE 5.4 and Cesium for Unreal 2.x public APIs. The first build on a real workstation *will* surface include
and signature mismatches; that is expected and is the first verification gate below. Until that gate is passed, the
browser client in this repository remains the running vertical slice.

Everything that is procedural, fictional or approximate is labelled as such in the data tables and in every HUD
notice the client emits (see `UTerraGameSettings::ProceduralContentNote`). Nothing here is a survey.

## Installation requirements (real machine)

| Item | Requirement |
|---|---|
| Engine | Unreal Engine **5.4 or newer** via the Epic Games Launcher (5.4 is the version the code targets; 5.5/5.6 should work with minor API fixes). |
| Windows toolchain | Visual Studio 2022 17.8+ with the **"Game development with C++"** workload, **Windows 10/11 SDK** (10.0.22621+), .NET desktop runtime. |
| macOS toolchain | Xcode 15.x (Apple silicon or Intel); Metal SM6 GPU. Chaos Vehicles and Nanite are supported; Lumen HWRT is not. |
| Cesium for Unreal | Install from Fab (https://www.fab.com/listings/cesium-for-unreal), version **2.x**. The code uses `ACesiumGeoreference::TransformLongitudeLatitudeHeightPositionToUnreal`, `ComputeEastSouthUpToUnrealTransformation`, `UCesiumGlobeAnchorComponent`, `UCesiumOriginShiftComponent` and `ACesium3DTileset::SetUrl/SetIonAssetID`. |
| Mass traffic | `MassEntity`, `MassGameplay`, `MassAI`, `MassCrowd`, `ZoneGraph` ship with the engine. **`MassTraffic` does not**: it comes with Epic's *City Sample* on Fab; the `.uproject` marks it `Optional` so the project opens without it (no C++ depends on it). |
| Disk | ~150 GB free: engine (~60 GB), Visual Studio (~30 GB), Cesium tile cache and derived data (~40 GB), project intermediates. |
| GPU | ≥ 8 GB VRAM for Nanite + Lumen + VSM at 1080p60 (RTX 3060 Ti / RX 6700 class or better). Lumen requires SM6 (DX12 or Metal). Below 8 GB use the `Performance` preset. |
| RAM | 32 GB recommended (16 GB minimum with the shader compiler throttled). |
| Network | Cesium ion (optional token), Google Map Tiles API (optional key), OpenStreetMap-derived tilesets. |

## Credentials and licensing

Copy `Config/Secrets.ini.example` to `Config/Secrets.ini` and fill in what you have; or set the environment variables
`TERRA_CESIUM_ION_TOKEN`, `TERRA_GOOGLE_TILES_KEY`, `TERRA_TILESET_URL`. `UTerraSecretsSubsystem` reads them at
start-up, applies the ion token to Cesium's runtime settings and picks the terrain source in this order:

1. **Google Photorealistic 3D Tiles** (`GoogleTilesKey`) — streamed from `tile.googleapis.com`. Conditions of the
   Google Map Tiles API terms that matter here: Google attribution must stay visible whenever tiles are on screen
   (Cesium's credit overlay is forced on), tiles may not be cached across sessions or used offline, the attribution
   may not be hidden or altered, usage is billed per root request after the free quota, and keys must never ship
   inside a build. This is an *optional* visual upgrade, not a dependency.
2. **Custom tileset URL** (`TilesetUrl`) — for example a tileset you built from open data.
3. **Cesium World Terrain** (ion asset 1) when an ion token exists; Cesium OSM Buildings (asset 96188) can be added the
   same way.
4. **Open fallback (no keys)** — the same stack the browser client uses: open terrain (AWS Terrarium / Copernicus
   DEM converted to quantized-mesh), OSM buildings (ODbL, "© OpenStreetMap contributors"), Natural Earth (public
   domain), open railway/road/airport data (OSM, ourairports.com). Attribution lines are in `ATTRIBUTIONS.md`.

`Config/Secrets.ini` and any `*Secrets*.ini` are git-ignored; the example file is the only tracked one.

## Data pipeline (verified in this repository)

`src/data/maharashtra/**` is the single source of truth for both clients.

```
node scripts/export-unreal-data.mjs          # regenerate unreal/TerraInfinite/Content/Data/*.json
node scripts/export-unreal-data.mjs --check  # exit 1 if the committed tables are stale
npm test                                     # tests/unit/exportUnrealData.test.ts enforces the same
```

The exporter loads the TypeScript modules through Vite (aliases and extension-less imports resolve as in the app),
recognises tables **by shape** (so each track may name its exports freely), writes one UDataTable-compatible JSON
array per table (`Name` = id, PascalCase fields matching the `FTerra*Row` structs) and a `Manifest.json` listing
every table with its status (`exported` / `missing-in-source`). Campus specs and interior-grammar parameters are
matched by export name (`/campus/i`, `/grammar/i`) because their types belong to the interiors track; unknown fields
are preserved in `ExtraJson`. At run time `UTerraDataSubsystem` parses the JSON with `FJsonObjectConverter`, so no
editor import step exists; `DefaultGame.ini` stages `Content/Data` as loose files so packaged builds find it.

| Table | Row struct | Source today |
|---|---|---|
| Spawns.json | FTerraSpawnRow | `MAHARASHTRA_SPAWNS` (10 rows) |
| Destinations, Stations, RailCorridors, Airports, Ports, WaterRoutes | FTerraDestinationRow … FTerraWaterRouteRow | empty until the data/journeys tracks land their exports |
| Campuses, CampusBuildings | FTerraCampusRow, FTerraCampusBuildingRow | empty until the interiors track exports a campus spec |
| InteriorGrammar | FTerraInteriorGrammarRow | empty until the interiors track exports a grammar |

## Build steps

1. Clone the repository and run `npm ci && node scripts/export-unreal-data.mjs` (keeps `Content/Data` fresh).
2. Install UE 5.4+, the toolchain and Cesium for Unreal (table above).
3. Right-click `unreal/TerraInfinite/TerraInfinite.uproject` → **Generate Visual Studio project files** (or
   `<UE>/Engine/Build/BatchFiles/GenerateProjectFiles.bat -project=<path>\TerraInfinite.uproject -game`).
4. Build the **Development Editor** target from Visual Studio / Xcode, or from the command line:
   `<UE>/Engine/Build/BatchFiles/Build.bat TerraInfiniteEditor Win64 Development -project=<path>\TerraInfinite.uproject`.
   Expect compile errors on the first attempt (see gates); fix them file by file — `Geo/TerraGeo.cpp` is the one
   place that touches Cesium's API and is the most likely to need adjusting to the installed plugin version.
5. Open the project in the editor. Enhanced Input, the collision profiles and the Terra settings sections are all
   config-driven, so no Blueprint assets are required to reach the main menu-less start (the game mode spawns the
   player at `DefaultSpawnId`).
6. Create the benchmark map (next section) and press Play.

## Benchmark map (`/Game/Maps/L_Benchmark`)

Binary `.umap` files cannot be authored in this repository. Create it once:

1. File → New Level → Empty Open World (World Partition on). Save as `Content/Maps/L_Benchmark`.
2. World Settings → GameMode Override = `TerraGameMode`. Enable HLOD (an `HLOD_Instancing` layer for buildings).
3. Add a **CesiumGeoreference**; set its origin to the Gateway of India spawn (lat 18.9218, lon 72.8340, height 10).
4. Add a **Cesium3DTileset** for terrain (Cesium World Terrain via ion, or your open tileset). Optionally call
   `UTerraSecretsSubsystem::ConfigureTileset` on it from a level Blueprint to switch sources by credentials.
5. Add **CesiumSunSky**, a **SkyAtmosphere**, **ExponentialHeightFog**, a **PostProcessVolume** (unbound, Lumen on).
6. Add a **Water** body ocean actor at height 0 if the Water plugin is enabled.
7. Play. Console commands:

```
terra.Spawn gateway-of-india          move to a Spawns.json row
terra.GoTo 18.9432 72.8236 340        teleport (height sampled from terrain)
terra.Vehicle.Spawn                   spawn the Chaos vehicle in front of the player (F to enter/exit)
terra.Journey.Train <corridorId>      board a train (needs RailCorridors.json rows)
terra.Journey.Flight <from> <to>      fictional flight between Airports.json rows
terra.Journey.Ferry <routeId>         board a water route
terra.Quality Performance             apply a preset (Low|Medium|High|Ultra|Performance)
terra.Diagnostics                     toggle the overlay (also F3)
terra.Benchmark.Run [ids] [duration=60]   visit the benchmark spawns, write Saved/Benchmarks/benchmark-*.json
terra.Benchmark.Write [label]         write the current stats window
terra.Data.Reload                     re-read Content/Data/*.json
```

The benchmark JSON contains the hardware probe (CPU, cores, GPU, RHI, feature level, RAM, VRAM, resolution, OS,
engine version), the active preset/governor rung/screen percentage, the current snapshot (FPS current/avg/1 % low,
frame/game/render/GPU ms, RAM, VRAM used/total, draw calls, actors, active cells, interiors) and one entry per leg.
Paste the summary into `PERFORMANCE.md` when you have real numbers; the sandbox cannot produce any.

## Controls (DefaultInput.ini)

WASD / left stick move, mouse / right stick look, Space jump (parkour assist inside zones), Shift run, **E** interact,
**F** enter/exit vehicle, **V** camera cycle (first person / third person / far chase), **H** horn, **L** lights
(off/low/high), **Q / R** indicators, **Z** hazards, **X** wipers, Space handbrake while driving, Backspace vehicle
reset, F3 diagnostics, Esc pause.

## Verification gates (all open — none can be closed in the sandbox)

| # | Gate | How to close it |
|---|---|---|
| 1 | The module compiles (Development Editor, Win64 or Mac) | Build as above; fix API drift, commit the fixes. |
| 2 | The editor opens the project and `L_Benchmark` plays without errors | Create the map; check the Output Log for `LogTerra` warnings (missing georeference, missing tables). |
| 3 | Spawn/teleport place the character on the terrain at every `Spawns.json` row | `terra.Spawn <id>` for all 10 ids; screenshot each into `docs/screenshots/unreal-*.png`. |
| 4 | Walk, run, stairs, elevator, parkour mantle, fall protection behave as described | Place an `ATerraElevatorVolume`, an `ATerraParkourZone` and a tall block; test each. |
| 5 | The Chaos vehicle drives with wheels | Needs an **original** skeletal vehicle mesh with wheel bones + a wheel setup on the movement component; today the pawn is a wheel-less physics body. |
| 6 | Journeys move the vessel along corridors and the passenger camera works | Needs `RailCorridors.json` / `Airports.json` / `WaterRoutes.json` rows from the journeys track. |
| 7 | Interiors: procedural shell at a campus building, hero Level Instance for a registered id | Needs `CampusBuildings.json` rows and at least one hand-crafted level. |
| 8 | `terra.Benchmark.Run` writes a JSON with plausible numbers at 1080p on the target GPU | Run it; attach the file to `PERFORMANCE.md`. |
| 9 | Quality governor steps down/up the ladder under load | Force load (`r.ScreenPercentage 200`), watch `LogTerra` "Governor:" lines. |
| 10 | Packaged build stages `Content/Data` and finds the tables | Package Shipping, run, check `LogTerra` "Loaded N rows". |

## Known skeletons (called out in code comments too)

* `UInteriorGeneratorSubsystem::FurnishRoom` only logs — no prop assets exist yet. Walls, floors, doors, stairs,
  lifts and rooftop railings are real geometry (instanced engine cubes).
* `ATerraVehiclePawn` has lights/indicators/horn/wipers/scuff FX/stuck reset but no wheel setup (gate 5).
* `ATerraJourneyVessel` bodies are scaled cubes; intermediate station stops are not modelled (trains run
  origin → terminus with an acceleration/brake profile).
* Mass crowds/traffic are enabled as plugins but not configured; `terra.Traffic.Density` / `terra.Crowd.Density`
  are read by the governor and exposed for the Mass processors to consume.
* No UMG HUD widget exists; `ATerraPlayerController::OnNotice` and `GetInteractionPrompt()` are the hooks for it,
  and the diagnostics overlay uses `AddOnScreenDebugMessage`.
