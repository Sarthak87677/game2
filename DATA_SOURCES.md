# Data sources

Terra Infinite streams everything through replaceable adapters (`src/data/adapters/`). Nothing planet-scale is stored in the repository: only the tiny public-domain Natural Earth reference vectors (≈4 MB after processing) are vendored under `public/data/ne/`, regenerated by `npm run assets:process`.

Provenance vocabulary used in the app and below:

| Label | Meaning |
|---|---|
| **measured** | Surveyed / observed geographic data used as-is. |
| **inferred** | Derived by a model from coarse data (e.g. Köppen class from climate normals interpolation). |
| **procedural** | Generated visual detail that is geographically plausible but not real (vegetation, generic buildings, simulated weather). |
| **live** | Optional network observations fetched at run time. |

## Usage limits and etiquette

* **Overpass**: one request at a time, ≥1.5 s spacing, 25 s server timeout, responses cached 7 days in IndexedDB, automatic back-off on HTTP 429/504. Never bulk-download.
* **Nominatim**: ≤1 request/second, results cached per session, reverse geocoding only below 4 km altitude and only when the camera moved >300 m.
* **OSM raster tiles**: light interactive use only; not the default layer.
* **Esri World Imagery**: allowed for light/non-commercial use; add an ArcGIS key for production deployments.
* **AWS Terrain Tiles**: no key, S3 egress paid by AWS Open Data; tiles are cached locally (configurable budget).

## Procedural interiors and the hero campus

Interiors (`Enter … (procedural interior)`) and the SGIS-inspired campus use **no external dataset**. Room layouts are generated deterministically from the building footprint (OpenStreetMap outline when online or in the fixture, otherwise the procedural near-field footprint) with a seed derived from the footprint centroid, so the same building always yields the same interior. The campus origin (16.7335, 74.4015) is an approximate public map position (±300 m); its layout is invented. Both are labelled fictional/procedural in the world and the HUD.

## Not used

* Google Maps/Earth tiles, Apple Maps, Mapbox raster (restricted terms or keys required).
* Commercial 3D city models (restricted). Building geometry comes only from OSM or procedural generation.
* No datasets are scraped; all access is through documented public APIs or tile endpoints.

## Adding a source

Implement `TerrainAdapter`, `ImageryAdapter`, `FeatureAdapter` or `GeocodingAdapter` (`src/data/adapters/types.ts`, `src/data/adapters/features/types.ts`, `src/data/geocoding/types.ts`), fill in a `DataSourceInfo` record (this table is generated from the same fields at run time in the Data panel), register it in `src/data/adapters/registry.ts`, and add a row here plus an entry in `ATTRIBUTIONS.md`.
